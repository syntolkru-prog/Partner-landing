# Партнёрский лендинг Syntolk

Корневые `index.html`, `Syntolk-product-demo.html` и `Syntolk-partners-assets/` — копия того же сайта для статического просмотра и GitHub Pages. Для публикации с обработчиком используется `public/`; при обновлении сайта синхронизируйте обе копии.

В `public/` — сайт с фотографиями и интерактивным HTML-макетом продукта. `Syntolk-product-demo.html` — отдельный самодостаточный экран, который можно открыть без сервера. `server.mjs` раздаёт сайт и принимает заявки через `POST /api/partner-applications`. Это подготовленный пакет для публикации; действующий домен и почта ещё не подключены.

## Запуск на сервере

Нужен Node.js 24 или новее, постоянный диск и HTTPS на публичном домене. Обычный статический хостинг, включая GitHub Pages, не запускает этот обработчик.

1. Распакуйте пакет в отдельную папку на сервере.
2. Выполните `npm ci`.
3. Скопируйте `.env.example` в `.env` и заполните параметры. Не добавляйте `.env` в Git и не размещайте его в `public/`.
4. Выполните `npm test`.
5. Запустите `npm start` через менеджер процессов. Настройте автоматический запуск после перезагрузки.
6. Настройте HTTPS reverse proxy на `127.0.0.1:3000`. Проксируйте весь сайт, включая `/api/partner-applications`, сохраняя заголовок `Origin`.

### Параметры

| Параметр | Значение |
| --- | --- |
| `PUBLIC_ORIGIN` | Фактический HTTPS-домен, без пути и завершающего `/`. Домен в примере — заготовка. |
| `HOST`, `PORT` | По умолчанию `127.0.0.1:3000`, за reverse proxy. |
| `DATA_DIR` | Постоянная закрытая папка вне `public/`. Относительный путь считается от папки запуска. |
| `SMTP_HOST`, `SMTP_PORT` | SMTP-сервер вашей почты. |
| `SMTP_SECURE` | `true` для порта 465; `false` для STARTTLS, обычно порт 587. TLS обязателен в обоих случаях. |
| `SMTP_USER`, `SMTP_PASS` | Данные отдельной почтовой учётной записи или пароль приложения. Заполняются на сервере. |
| `SMTP_FROM` | Разрешённый почтовым сервисом адрес отправителя, без отображаемого имени. |
| `APPLICATION_TO` | Адрес получения заявок; по умолчанию `support@syntolk.ru`. |
| `TRUST_PROXY` | `true` только при собственном reverse proxy, который заменяет `X-Forwarded-For` адресом клиента. Иначе `false`. |

Сервер проверяет SMTP при запуске. Если проверка не проходит, исправьте настройки до публикации. Для отправителя настройте SPF/DKIM по инструкции вашего почтового провайдера.

## Что происходит с заявкой

Форма принимает обязательные имя, телефон, email или Telegram и направление, необязательное описание и согласие на обработку данных. Направление выбирается одной из восьми радиокнопок. Ошибки показаны рядом с полями, при отправке повторное нажатие блокируется. Телефон проверяется на клиенте и сервере: 10–15 цифр, допустимы код страны с `+`, пробелы, скобки и дефисы; в заявке сохраняется номер без разделителей. Успешный ответ возвращается после записи заявки в `DATA_DIR`. Затем сервер отправляет уведомление, включая телефон, на указанный адрес.

При сбое почты заявка остаётся в очереди; доставка повторяется раз в минуту и после перезапуска. Состояние `delivery: "sent"` означает принятие уведомления SMTP-сервером, а не прочтение письма получателем. При аварии между отправкой письма и записью статуса возможно повторное уведомление с тем же номером заявки.

Повторная попытка формы с теми же данными использует тот же идентификатор и не создаёт вторую заявку. Проверяются поля, размер запроса, источник запроса и частота отправки. Ловушка для автоматических заполнений скрыта от обычного пользователя.

JSON-файлы заявок содержат контакты. Доступ к `DATA_DIR` должен быть только у серверного процесса и администратора; каталог не должен раздаваться веб-сервером. Настройте резервное копирование и срок хранения заявок в соответствии с вашей политикой. Секреты и заявки в архив не включены.

## Проверка после публикации

- Откройте страницу на компьютере и телефоне. Проверьте меню, фотографии, вкладки продукта, поиск документов, переход к источнику и калькулятор.
- Отправьте свою контрольную заявку. Проверьте номер подтверждения, запись в `DATA_DIR` и поступление письма.
- Проверьте, что `.env`, серверные файлы и `DATA_DIR` недоступны через публичный URL.
- Доступность формы проверяется на опубликованном сайте. При открытии HTML через `file://` выводится пояснение и ссылка для связи по почте.

## Контент

Главный экран и четыре карточки поддержки сохранены. Повторы в карточках аудиторий убраны; блок вознаграждения расположен сразу после аудиторий. Раздел «Как привлекать клиентов» удалён вместе со ссылками на него в меню.

Демонстрация продукта — HTML-макет по интерфейсу Syntolk: 12 загруженных документов по разным отраслям, пример вопроса, ответ с этапами запуска проекта и кликабельная ссылка на подтверждающий раздел. Документы, вопрос и ответ придуманы по прямому указанию заказчика; макет обозначен как демонстрационный. Поиск, фильтры папок, вкладки и переход к источнику работают локально. Реальный ИИ в макете не вызывается. Фотографии остальных блоков сохранены, крупный PNG сжат в WebP, встроенные изображения вынесены в отдельную папку.

Сроки выплат, минимальная сумма, возвраты и точные правила закрепления клиентов не были предоставлены. В FAQ оставлены общие формулировки о согласовании условий при подключении; конкретные правила нужно вставить после утверждения.

## Выполненные проверки

Девять серверных тестов проверяют запись заявки, отсутствие дубликатов, Telegram, обязательный телефон и международные номера, неверные поля, Origin и формат запроса, ограничения, закрытость серверных файлов и повтор доставки после сбоя. Письма в ходе этих тестов не отправляются.

Шесть тестов формы проверяют ошибки и фокус, обязательный телефон, отправляемые данные, повтор после сбоя, блокировку двойной отправки и поведение локального предпросмотра. Они исполняют JavaScript формы с имитацией DOM без браузера.

Четыре теста HTML-макета проверяют вкладки и клавиатуру, открытие источника и возврат, поиск с фильтром отрасли, выбор папки и возврат ко всей базе. Это проверки событий JavaScript без браузера; они не заменяют визуальную проверку.

Проверены синтаксис скриптов сайта, внутренние ссылки и наличие локальных ресурсов.

Мобильная компоновка выделена в `style#mobile-layout`. До 1000 px фото и текст карточек находятся в отдельных строках: фотографии имеют пропорцию 3:2 и `object-fit: cover`, высота карточек зависит от содержимого. До 600 px карточки идут в одну колонку, боковые поля страницы составляют 16 px. На планшетах остаются две колонки. Исправлены исходные размеры четырёх изображений в HTML, без изменения самих файлов. Убраны вложенные отступы вокруг экрана продукта, уменьшены поля калькулятора и разделов, пересобраны мобильная шапка, форма и подвал. Поля ввода имеют шрифт 16 px для предотвращения автоматического увеличения страницы в iOS. На планшетах контакты занимают две колонки, на телефонах — одну.

Статическая проверка каскада CSS выполнена на 20 ширинах от 320 до 1440 px, включая распространённые размеры телефонов и планшетов в обеих ориентациях. Отдельно проверена ширина шапки при 320 px и подписей вариантов направления на всех ширинах 320–600 px по метрикам шрифта Onest. Прежние стили и скрипты не изменены; новые правила ограничены шириной до 1000 px. Это проверка исходника, а не браузерного рендеринга.

Визуальная проверка самого локального лендинга на мобильном и десктопном размерах не завершена: доступ к локальной странице был заблокирован политикой браузера. Перед публикацией остаётся проверить страницу в Safari на iPhone и Chrome на Android.
